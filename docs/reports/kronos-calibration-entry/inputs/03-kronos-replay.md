# Standalone Kronos synthetic replay

Every run is **SYNTHETIC_MECHANICS_ONLY**. Economic evaluation, strategy testing and trading authorization are false. This package imports no live traders, reads no market bars or credentials, trains nothing, and offers no historical-input CLI. Existing inference smoke, readiness and economic preflight gates are unchanged.

From the repository root:

```sh
/root/Silver-Bullet-ML-BMAD/.venv/bin/python -m research.kronos_replay --output-dir /tmp/kronos-synthetic-new
/root/Silver-Bullet-ML-BMAD/.venv-research/bin/python -m research.kronos_replay --provider cached --output-dir /tmp/kronos-cached-new
```

Use a fresh destination each time. Cached mode verifies the pilot's exact source/checkpoint hashes, loads once on CPU and uses local assets only. It never downloads. Run long cached jobs with `nohup` and a log. Stub mode is deterministic and fast. The bundled fixture supplies generated prices and six explicit sessions, including a DST offset transition and a synthetic short session. These dates do not authenticate an exchange calendar.

`run_replay(bars, sessions, provider, costs)` accepts an ordered iterable of contract-labelled OHLCV dictionaries and explicit timezone-aware `Session` objects. Timestamps denote **minute interval opens**, unlike the existing smoke pilot's end-labelled input hypothesis. The engine consumes exactly the scheduled minute sequence without sorting, filling gaps or inventing sessions. Each session consists of whole 15-minute buckets anchored at its opening. Aggregated timestamps denote interval closes and carry New York calendar features.

At each supplied minute, validation precedes fills; its opening executes available orders, then its completed OHLCV joins the current bucket. Only 128 completed same-contract bars are supplied to `ForecastProvider.forecast(context, future)`. The provider returns three DataFrames with the pilot's six columns and four exact future timestamps. All three terminal closes determine direction relative to the last observed close. Any invalid path or provider exception requests flat and retains error evidence. Momentum compares that close to four bars earlier with identical warmup and horizon eligibility; the third arm stays flat.

Decision availability is close plus modeled latency. All three arms execute at the first minute open **strictly later** than availability, in availability order. A signal at 10:00 with zero latency therefore fills at 10:01. No forecasts are made if the one-hour horizon extends beyond the explicit session close. Existing targets remain until the pre-known flatten at the final minute's open. That flatten overrides latency and cancels pending orders. Missing final-minute data cannot create an exit. Missing, duplicate, extra or malformed minutes produce INCOMPLETE while preserving exposure and pending orders. Contract changes reset context and require flat accounts, no pending orders and no partial bucket.

Execution uses one contract, $2 per point and .25-point ticks ([CME contract specification](https://www.cmegroup.com/markets/equities/nasdaq/micro-e-mini-nasdaq-100.contractSpecs.html)). `--latency-seconds`, `--fee-per-side` and `--slippage-ticks` describe synthetic software examples only. Repeated targets produce no fills; reversals close then open, charging each side. Adverse slippage is embedded in fill prices and separately disclosed; do not subtract it again from equity. Realized PnL is before fees and includes fill-price slippage; unrealized PnL marks remaining exposure at observed minute closes. Net equity is realized plus unrealized minus fees. Turnover counts filled contract sides. Drawdown tracks net equity at fills and minute-close marks, starting at zero. Proposed fills and account updates are checked for positive execution prices and finite arithmetic before a position change is committed. Incomplete runs' marks remain the last valid observation.

Artifacts include protocol/pins/code hashes, synthetic input, schedules, aggregates, raw forecast paths, decision targets, fills, minute equity and terminal account/pending state. The hash manifest binds all artifacts; only a successful replay writes COMPLETE.json, failures write INCOMPLETE.json. A complete replay can contain invalid forecasts handled by the registered flat fallback; inspect decision errors before interpreting model behavior. Serialization/filesystem failures cannot guarantee a final marker. CSVs belong to the synthetic-scoped protocol and manifest and are not economic evidence.

The next gate remains a separate committed economic protocol with admitted untouched data, justified costs and target effect, frozen comparisons and an experiment-specific power gate. Neither synthetic PnL nor seed variation establishes predictive edge or calibrated uncertainty.
